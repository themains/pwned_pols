## How Often Is Politician Email Data Breached? Evidence from HIBP

This repository contains the replication package for a study of public breach exposure among politician email addresses. The analysis covers 12,385 observed addresses from 59 countries. The unit is an email address, not a politician; the estimates are lower bounds because addresses and public HIBP incidents are incomplete. The manuscript reports primary, Tier-3-only, and password-related seriousness definitions, HC3 inference, wild-cluster diagnostics, hierarchical bootstrap intervals, and a 10,000-draw Shapley decomposition.

The final manuscript is [ms/ms.pdf](ms/ms.pdf). Analytical handoffs are typed RDS files in `analysis/`; tables are LaTeX fragments/wrappers and figures are PDF/PNG. The frozen input data remain in `data/` and are not regenerated by the analysis build.
### Reproduce the analysis

Create the project environment, then run:

```sh
make setup
make VENVPATH=venv verify
```

The build checks frozen-input hashes, blocks data-collection notebooks, runs the analysis dependency chain, validates notebook hygiene, audits manuscript numbers, and compiles the PDF. If using the checked-in reproducible environment, replace `venv` with `.venv-repro`.

The analysis pipeline is:

1. `scripts/06_everypol_summ.R` builds the frozen email-level analysis handoff.
2. `scripts/07_breach_summ.ipynb`, `scripts/08_breach_prob.R`, and `scripts/09_breach_rate_evolution.ipynb` produce first-stage exhibits and inference.
3. `scripts/11_crosscountry.R` joins typed country effects to the frozen covariates and produces HC3, hierarchical-bootstrap, Shapley, and seriousness-sensitivity outputs.
4. `scripts/12_format_ms_tables.py` applies the shared table wrapper; `scripts/13_check_ms_numbers.py` audits manuscript quantities.

Data acquisition and source-data assembly notebooks are intentionally outside the build. Their inputs are frozen and checked by `make check-inputs`.
